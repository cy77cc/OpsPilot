# Host 终端页布局与文件预览重设计（终端优先 + Modal 编辑）

## 1. 背景与目标

当前 `主机终端` 页面存在两个核心问题：

1. 页面留白较多，导致终端可视容器偏小。  
2. 终端底部内容在部分窗口尺寸下会被遮挡。  
3. 文件点击后在右侧内嵌编辑，空间不足，阅读/编辑体验差。

本次设计目标：

- 采用终端优先布局（大屏约 70/30）。
- 修复底部遮挡，保证终端最后一行可见。
- 文件编辑改为点击后使用 Ant Design `Modal` 展示与编辑。

## 2. 范围

### In Scope

- `HostTerminalPage` 页面布局重排。
- 文件预览/编辑从右侧内嵌 Card 改为 Modal。
- 保留并兼容现有文件管理动作（上传/下载/重命名/删除/目录跳转）。

### Out of Scope

- SSH/终端协议层变更。
- 文件 API 协议变更。
- 新增复杂文件编辑能力（多标签、diff、协同编辑等）。

## 3. 方案比较与选型

### 方案 A（采用）：轻量重排

- 保留现有页面主体结构，调整为严格的视口高度弹性布局。
- 左侧终端、右侧文件管理；编辑器迁移到 Modal。

**优点**：改动小、风险低、回归成本可控。  
**缺点**：视觉层级改进有限。

### 方案 B：双层容器重构

- 提炼通用 `TerminalWorkspace` 抽象后重做布局。

**优点**：结构长期更优。  
**缺点**：改动面大、验证成本高。

### 方案 C：抽屉式文件区

- 默认最大化终端，文件区改为折叠/抽屉。

**优点**：终端空间最大。  
**缺点**：交互变化较大。

**结论**：采用方案 A。

## 4. 交互与布局设计

## 4.1 页面结构

- 根容器使用 `height: 100vh`，以视口为基准组织空间。
- 顶部（面包屑 + 页面头）固定占用自然高度。
- 主体区域占剩余高度并设置 `min-height: 0`，内部滚动由子区域承担。
- 底部信息提示不再挤压终端可视区，避免最后一行被遮挡。

## 4.2 大屏布局

- 左侧终端区：约 70%。
- 右侧文件管理区：约 30%。
- 终端容器保持 `height: 100%`，确保 xterm 可自适应到可用高度。

## 4.3 小屏布局

- 保持上下堆叠（终端在上，文件区在下）。
- 文件编辑统一通过 Modal，不在侧栏内嵌编辑器。

## 4.4 文件点击行为

- 点击文件项触发读取。
- 读取成功后弹出 Modal 显示编辑器内容。
- 列表中当前打开文件高亮。

## 5. Modal 编辑器设计

- 组件：Ant Design `Modal`。
- 尺寸：`width: 80vw`，内容区总高约 `80vh`。
- 标题：显示文件路径，超长省略并保留 tooltip。
- 主体：Monaco Editor，`height: 100%`，暗色主题沿用现状。
- 底部操作：保存 / 取消。
- dirty 状态提示：内容变更后提示“内容已修改，记得保存”。
- 关闭防误触：存在未保存修改时弹确认。

## 6. 数据流与状态

新增/调整状态建议：

- `fileModalOpen: boolean`
- `modalFilePath: string`
- `modalContent: string`
- `modalEditing: boolean`
- `modalSaving: boolean`

流程：

1. 点击文件 `openFile(item)`。
2. 请求文件内容成功后写入 `modalFilePath/modalContent`，并 `fileModalOpen=true`。
3. 编辑时更新 `modalContent`，置 `modalEditing=true`。
4. 点击保存调用现有保存 API；成功后刷新目录并清理编辑态。
5. 关闭 Modal 时若 `modalEditing=true`，先走二次确认。

## 7. 异常处理

- 打开文件失败：保持 Modal 关闭，显示错误消息。
- 保存失败：Modal 保持打开，不丢失编辑内容，显示错误消息。
- 目录刷新失败：不影响已打开的 Modal 编辑会话。

## 8. 测试与验收标准

### 功能验收

1. 大屏下终端/文件区约 70/30。
2. 终端底部最后一行可见，无固定遮挡。
3. 点击文件后以 Modal 展示编辑器。
4. 保存成功后文件列表刷新并保持目录上下文。
5. 上传/下载/重命名/删除/目录跳转行为不回归。

### 回归建议

- 手工回归主机终端页面关键流程（连接、执行命令、滚动到底部）。
- 执行前端现有测试（至少包含 host/terminal 相关页面测试，如存在）。

## 9. 风险与缓解

- 风险：布局高度链设置不完整导致局部溢出。  
  缓解：统一补齐 `height: 100%` + `min-height: 0` 约束并在多窗口尺寸验证。

- 风险：Modal 关闭与未保存确认逻辑冲突。  
  缓解：将关闭入口统一走同一确认分支，避免重复分叉。

## 10. 实施备注

- 优先最小可回滚改动，不引入新依赖。
- 优先复用现有 `openFile/saveFile` 与消息提示逻辑。
- 该设计完成后进入 `writing-plans` 阶段拆解实施任务。
